# Strategy Version Curation Policy (R38)

## Status

Decision: **explicit retention rules** for the research factory and
auto-loop. Lessons from MODELO SP500 -- JADE went to v112 and NAOMI to
v14 without an archival policy, and the resulting clutter masked the
actually-promoted versions.

This document defines what is retained when a strategy version is
superseded, and what is garbage-collected. Pair with R39 (graveyard
CLI) and R140 (lifecycle SLA + auto-archive).

## Strategy version lifecycle

A strategy version moves through these states:

| State | Set by | Retention |
|-------|--------|-----------|
| `proposed` | factory submit | 30 days |
| `triaged` | triage pipeline | 90 days |
| `promoted` | OOSGuard countersign | indefinite (with cap, see below) |
| `live` | live runner | indefinite (with cap) |
| `paused` | data-quality / anomaly trigger | 365 days |
| `archived` | SLA expiry / operator decision | indefinite (cold) |
| `superseded` | new version approved | retain spec + final report only |

A version is "superseded" when a newer version of the same strategy
family is promoted. The superseded version moves out of the active
research-archive index and into the cold archive.

## What gets retained per state

### Always retained (regardless of state)

- The `StrategySpec` (canonical params, hash, signing identity).
- The promotion-time validation report (markdown + JSON).
- The audit-chain entries that name this version.
- The reproducibility witness (R146) for the final live snapshot.

### Retained until cap is reached

Promoted / live versions may accumulate large per-run artefacts:

- Per-bar weights, per-trade fills, per-day equity series.
- Daily-ops report PDFs.
- Walk-forward fold results.
- GA fitness traces.

Cap: **the latest 90 days** of per-run artefacts per strategy. Older
artefacts are aggregated into a quarterly summary and the raw rows
are deleted from hot storage; the summary stays online.

### Retained for triage horizon, then garbage-collected

Speculative variants (state `proposed` or `triaged`) accumulate fast:

- Triage variants generated by the factory but never promoted.
- Auto-loop dev runs.
- Mutation / GA candidates that scored below the promotion threshold.

After the triage horizon (default 90 days), these are dropped from
hot storage. The aggregate counts ("8,213 variants triaged in
2026-Q1") are retained as a single roll-up record.

### Hard caps

The factory enforces a per-family version cap to avoid the v112
problem: **at most 50 superseded versions per strategy family** before
the oldest are physically deleted (with an audit-chain receipt).
Operators can override per-family if a strategy genuinely needs more
history (e.g. for regression testing); each override is recorded.

## What gets garbage-collected

These are explicitly safe to delete:

- Intermediate backtest snapshots produced during a run (the final
  snapshot is retained; intermediate ones are reproducible from the
  spec).
- GA population JSONs from rejected runs.
- Temporary cache files (under `QF_CACHE_DIR`).
- Compiled artefacts (`__pycache__`, `*.pyc`, `*.so`).

Garbage collection is opt-in:

```bash
forge research gc --older-than 90d --dry-run
forge research gc --older-than 90d
```

## Operator override

Any retention rule above can be suspended for a specific version with
an audit-chain "retain forever" pin:

```bash
forge research pin <strategy_id> --reason "regression test fixture"
```

A pinned version refuses to be archived, garbage-collected, or hard-
capped. The pin is recorded with operator identity + timestamp so the
override is auditable.

## Auto-archive on SLA expiry (R140)

When a strategy hits its SLA expiry (default 365 days), the lifecycle
pipeline moves the version to `archived`. The spec, validation
report, and witness stay; everything else is treated as "older than
retention horizon" and is summarised + dropped per the rules above.

## Implementation status

- [x] Spec retention -- handled by `research/factory/registry.py`.
- [x] Audit-chain entries -- handled by `agent_gateway/audit.py`.
- [x] SLA expiry hook -- handled by `research/lifecycle.py` (R140).
- [x] Cold archive write path -- handled by `research/factory/`
      registry append.
- [ ] `forge research gc` CLI command (follow-up to this policy).
- [ ] `forge research pin` CLI command (follow-up to this policy).
- [ ] Hard-cap enforcement (per-family 50-supersede cap) is policy-
      level today; the factory will refuse to write the 51st only
      after the per-family enforcement lands.

## Out of scope

- Encryption of cold archives (handled by `compliance/encryption_at_rest.py`).
- Cross-region replication of cold archives (operator infra concern).
- Per-tenant retention horizons (RBAC concern, see R43).
